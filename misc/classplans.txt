class Dog {
   num age = 5;
   str name;
}



class Dog -> 
	CDEF Dog -> creates new class entry called Dog in the vm class definition table

	'Dog' stays cached on the vm for now
num age -> 
	CNUM age -> adds num value called age (operand) to class named 'Dog' (cached as last created class) 
str name ->
	CSTR name -> adds str value called name (operand) to class named 'Dog' (cached as last created class) 


Ends with class entry in c++ vm of: (pseudocode)
    "Dog":
	num age
	str name
	

When using the class:

new Dog() newdog;

PUSH Dog
INSTC newdog (instantiate class)

vm searches for class called Dog, if found, parse the members stored in the class entry (in this case num age, str name)
Then create a new class member holder in the vm with each member in the current scope (similar to var and table scopes)

Vm class holder would now look like
Scope global:
	newdog:
		double age = 0;
		std::string name = "";


After this:

Compiler recognizes newdog::age = 5; as setting a class member
and print(newdog::age) as evaluating the member of a class

it would turn into

newdog::age = 5; -> 

PUSH newdog
PUSH age
CSTORE 5

VM pops a (classname), pops b (member), searches for classname in current scope upwards until found, then sets that class.age to 5

and print(newdog::age) would be evaluated to:

PUSH newdog
CLOAD age

VM pops a (classname), searches for classname in current scope upwards until found, then loads the value of class.age to stack
